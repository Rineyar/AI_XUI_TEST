## Для редактор(а/ов)
### API соглашения
#### tools <-> guards
Решайте сами, меня это не должно касаться. Гвард вызывается до функции, и если хочется, после.  
*Эту часть допишите сами*
#### core <-> guards
Core вызывает guard с параметрами:
```rust
pub struct ToolRequest
{
    pub module: &'static str,
    pub function: &'static str,
    pub args: Value
}
```
Который конвертируется в dict питоновский.
У него будет:
- Ключ module содержащий строку с именем модуля, откуда функция
- Ключ function содержащий строку с именем функции, вызванной
- Ключ args с json с аргументами, зависящими от функции
**Чё с этим делать решай сам, дорогой**
#### core <-> tools
##### Вызов функций
Core вызывает tool с kwargs. Т.е. в вашем случае нужно делать:
```python
def some_func(*, arg1, arg_named)
```
##### Возвращение результата
И return делайте что треубется. Если возвращать требуется что-то структурированное и/или объёмное, то делайте:
```python
return json.dumps(result)
```
Core это примет как строку и отдаст в LLM. Если это ответ для неё.
Если нет, то возвращайте *пока не уверен как*. И скиньте мне че возвращается.
##### Структурный стиль
В **.py** не допускается висящий код. Т.е. исполняемые объекты за пределами любых функций или \_\_main\_\_.
Переменные вне функций разренены.
В вашем модуле обязательно должен быть \_\_all\_\_ содержащий \[\] с именами функций в строках. Они обяназы соответствовать коду.
Т.е.:
```python
__all__ = ["some func"]

def some_func(...)
```
**ПЛОХО**

```python
__all__ = ["some_func"]

def some_func(...)
```
**ХОРОШО**
##### Правила импортов
Вы можете импортировать другие **.py** файлы рядом. Для этого пишете
```python
import other_file
```
**ВАЖНО!** Не использовать ***from import***
```python
from other_file import some_func
```
Просто не соберётся.
Для внешних библиотек по типу ***requests*** использовать ***from import*** разрешено.
##### Ну и просто просьба
Есть **files.py** ну и пишите там всё что свяязано с файлами. Для других областей сделайте аналогично.
#### tool <-> tool
Актуальная моя просьба выше. А так же как работайте сами с собой *решайте сами*.
### И дальше что
А дальше то, что после того как ты ~~высрал~~ сделал новый тулз или по *русски* инструмент нужно описать его в tools.md
Пример:
***rand_tool.py***
```python
from random import randint
from time import time
import randint

__all__ = ["get_rand_num"]

def get_rand_num(*, left, right, seed = 0) -> int:
    if seed == 0:
        random.seed(time())
    else:
        random.seed(seed)
    
    return randint(left, right)
```
Вот ты это добавил в tools/tools_py  
И теперь в tools.md добавляешь:
```markdown
## get_rand_num
Returns random integer between left boundary and right.
Callable with seed.

Arguments:
- `left` - left boundary
- `text` - right boundary

Supports:
- `seed` - random seed
```
И если он используется где-то в работе, то стоило бы описать его использование в skills.  
*Это уже ваше дело*.
